# amog.fun

Static site on Cloudflare Workers, deployed with `npx wrangler deploy` (wrangler is already OAuth'd on this machine). Pages are static assets; a small Worker (worker/index.js) runs only for /api/* (`run_worker_first`), so page loads never count as Worker requests. D1 database `amog-fun` (binding DB): add schema changes as new files in migrations/ and apply with `npx wrangler d1 migrations apply amog-fun --remote` (`--local` for wrangler dev). Secrets via `wrangler secret put`; local ones in .dev.vars (gitignored). Free plan: keep API work light (10 ms CPU per request).
Custom domains amog.fun and www.amog.fun are configured in `wrangler.jsonc`.

Conventions:
- Each project is a self-contained folder `public/<slug>/` served at `amog.fun/<slug>`. Keep projects quick & dirty and dependency-free (plain HTML/JS, CDN imports are fine).
- Games stay as paths (`amog.fun/<slug>`), not subdomains: shared assets cache once, one domain for SEO, zero per-game setup. All games share one origin, so localStorage keys MUST be prefixed `amog.<slug>.` (e.g. `amog.alchemy.v1`, `amog.nim.<variant>.score`); keep saves small (~5MB quota is shared by every game), use IndexedDB if a game needs more. Legacy exception: amog-space-program uses `asp-*` (don't rename, it would wipe saves).
- Caching lives in `public/_headers` (/assets/* = 1h + stale-while-revalidate; pages revalidate every load). Assets aren't fingerprinted, so don't set long `immutable` caching on them.
- Register every project in `public/projects.json` (slug, title, signature, blurb, tags, `group`, `short`, optional `featured`). The landing page renders from it: big cards for the `featured` ones (a rank 1–4; keep exactly four so the row never has an orphan), then a one-row-per-object catalog grouped by `group` (amog = play against Amog, clock = against the clock, long = long games, etc = trinkets & notes; GROUPS in public/index.html) with `short` as its one-liner. List order = order within a group, newest first.
- SEO: every page's <title>, canonical, Open Graph and breadcrumb JSON-LD live between `<!-- seo -->` and `<!-- /seo -->`, generated by `node tools/seo/seo.mjs` from its PAGES table (which also writes public/sitemap.xml). Add a new page to PAGES and rerun it (for VERTEX, then `npm run build:site --prefix vertex`). Google shows the site name "Magnussen Institute for Applied Fun" (WebSite JSON-LD on the home page) and the home page's favicon (public/favicon.ico/.svg, apple-touch-icon, og.png; redraw with `python3 tools/seo/icons.py` from public/). Other pages keep their own data: tab icons.
- `signature` is a joke morphism, e.g. `"dotsandboxes : Bored → Amused"`.
- Shared style: `/assets/amog.css` (dark starfield, Instrument Serif / STIX Two Text / JetBrains Mono, generator colors `--g1` cyan, `--g2` red, `--g3` lime). Put a `.topbar` with the `amog.fun∘` brand linking home on every page.
- Theme: Amog Magnussen is the founder & chief mathematician (group theory, category theory, obby). Copy leans into math jokes.
- LaTeX: include `<script src="/assets/math.js" defer></script>`; then `$inline$`, `$$display$$`, `\(..\)`, `\[..\]` render via KaTeX. Macros: \Hom \Cat \Grp \Set \id \op. Call `amogMath(el)` for dynamically inserted content; class `no-math` opts out. Blurbs in projects.json may use LaTeX.
- Theorem environments (same math.js): `\begin{lemma}[Title]\label{lem:x} ... \end{lemma}`, also theorem/proposition/corollary/conjecture/definition/example/remark/exercise/proof, starred = unnumbered, `\ref{lem:x}` links. Can span several <p>s. Reference + demo page: amog.fun/latex (public/latex/). Not listed in projects.json.
- math.js extras: `notation` env; `\N \Z \Q \R \C` built in; per-page macros via `<script type="text/tex-preamble">\def\im{\operatorname{im}}</script>`; tikz-cd diagrams (diagonals, bends, dashes, labels) via `<script type="text/tikzcd">...</script>` (KaTeX `CD` only does square grids). Documented on amog.fun/latex.

Buildings are inventory items: crafting puts them in `s.inv`, `place`/`pickUp`/`move` put them on and off the island (`count` = owned, `built` = placed). Clicking a building opens its machine panel (panels.js `machineBody`); there is no Machines card. Land is never bought: every completed quest adds a tile (`CONFIG.land`, engine `growLand`); don't reintroduce land or barrel costs. Tables and furnace-like machines can auto-make one item each once the Automation quest is done (`setAuto`). The Wilds (wilds.js; data `AREAS`/`MOBS`, `CONFIG.combat`/`pasture`/`enchant`/`grinder`) are areas that cost no tiles: Dark Platform combat with swords/armor/XP, the cow pasture, enchanting (`CONFIG.enchant.types`: Sharpness/Protection/Efficiency per tool kind plus mesh Efficiency/Fortune; applies to slotted tools too; past V costs ghast tears), and the Nether. Monsters unlock by peak level (`peakLevel`), never current level. One click crafts at most `CONFIG.craftMax` (64). Auto-make has a limit or `uncapped` (engine `autoLimit`). Pasture herds: cows come with it, sheep are lured (`CONFIG.pasture.sheep`, engine `HERDS`/`breed(s, kind)`). Late-game recipes use steel blocks. A recipe's `at` names the building it needs on the island ("table"). The Alchemy Lab is a STATION like the alloy smelter: transmutations live in data.js `LAB` (output -> in/n/time/needs; no fuel, one job per lab at a time, can auto-make; #30). Combat (#30): you pick an area (`s.zone`) and a random unlocked monster wanders in (engine `wander`); a swing recharges over `combat.cooldown` and early swings hit for less (`charge`); arena upgrades (`combat.difficulty`, `upgradeArena`/`setDifficulty`) scale monster HP/damage and XP/loot; `fuse` monsters (creepers) explode instead of hitting, `pierce` ones (witches) half-ignore armor; TNT is flat damage. Build quests say "craft and place", and the quest card flags a building that's crafted but not placed. There's no iron → gold → diamond: the lab makes copper and nickel (alloyed into constantan and invar for the later machines), and the late Philosopher's Stone (made in the lab from Nether drops) lets it turn diamonds into emeralds for emerald tools and the Terminal Object. Armor blocks armorPct per point up to armorSoft, then curves towards armorMax (engine armorBlock), so enchanting always helps. "You have this or better" compares tool tiers, never enchantments. Iron buckets milk cows (engine milk/drink). island.js caches the static scene and redraws on requestAnimationFrame; call its requestDraw, don't draw per game tick.

- amog.fun/mathcraft (public/mathcraft/): Mathcraft, prove theorems by crafting them (Pope Amog's #33). logic.js is the pure engine (page + Node; its header documents terms, paths and the step format). Blocks are statements: equations between numbers (0, S, +, ·, ^, small letters), or capitals, ⊥ and ⊤ joined by →, ∧, ∨, ↔ ("not P" is P → ⊥, no node of its own). ∨, ∧, ⊤, ↔ are definitions (A ∨ B = ¬A → B, A ∧ B = ¬(A → ¬B), ⊤ = ⊥ → ⊥, A ↔ B = (A → B) ∧ (B → A); airetho's design): `match` reads them as their definition wherever a pattern wants → (and a ↔ where it wants ∧, so the and-machines take a ↔ apart and make one), never the reverse (a ∨ machine doesn't take ¬A → B until it is folded). A proved ↔ is a machine with a lever like an equation (page kind `iff`): it rewrites any statement part of a block, or the whole block (path []), in either direction, and can always be stamped; P ↔ P ("If and only if") is the refl of statements, so the laws of logic are crafted by stamping it and rewriting one side. Numerals are definitions too (airetho): a typed 2 is the node ["#", 2], short for S(1); an S(b) pattern sees through it, a pattern 1 never matches S(0) until it is folded, and folding/unfolding is the same free `unfold` step (so a·1 = a and a^0 = 1 read as they should). Quantifiers (airetho): ["∀", ["v","a"], A] / ["∃", …] bind a number, ["@", ["v","P"], t, …] is a predicate P(t, …); ∃a. A is a definition, ¬∀a. ¬A. Paths count a quantifier's body and a predicate's arguments only (`kids`/`off`). `same` is up to bound names, `subst` never captures (it renames the binder), `vars` are the free ones. In a machine a predicate under its own quantifier is a slot for any statement about the bound number (`match` binds it to { lam, body }; nothing bound may leak into a slot); a fact held without slots never rewrites a letter a quantifier binds (`boundAt`). Tactics, all gates of the quantifiers world: `fix` (goal ∀: workshop "f" about one fixed number whose letter nothing in the workshop speaks about), `spec` (block ∀ + a number), `witness` (goal ∃ + a number: workshop "w"), `obtain` (block ∃: workshop "o" that holds the statement about a new letter). `holds(s, env, mod)` checks quantified statements in the integers mod 5, where every axiom and induction hold (no powers there); the random-play test uses it, with "trap" goals that are false and one careless rule away from provable, and each safety rule also has a direct test (verify by breaking the rule: the test must fail). `cases` (gate in logic, bought for And commutes, right after Or: by cases) takes a block apart: ∧ / ↔ into two blocks, ∨ into two workshops "p"/"q" that each hold one side. `unfold` steps fold/unfold for free (the Unfold machine on the floor, or the Scanner; its panel also has the page-only switch `save.plain` that writes every ¬P as P → ⊥); a goal is reached up to definitions (`sameDef`). Logic is classical from one bought axiom, Double negation (¬¬P → P); the and/or machines are quests. Equality machines (axioms, finished quests, equation hypotheses) rewrite any number subterm in either direction in place (a direction that leaves a slot open, 0 → a·0, takes a `fill`); any stated machine can `make` its statement as a block with the slots filled; `refl` makes t = t; machines with premises are rules: they take whole blocks in premise order, use them all up and put the conclusion in the first one's place (symmetry, transitivity, modus ponens, the and/or machines; a conclusion slot the premises don't fix, as in ⊥ gives P, takes a `fill`). A held implication (hypothesis "hN", A → B) is a rule too, without slots (logic.js `heldRule`; Scanner offers it). Modus ponens is a quest (airetho: it is Identity with P → Q in its slot), id `mp` like the machine the shop used to sell, so old proofs replay and the page marks it done for saves that had bought it; *Using an implication* and the bounty *Symmetry, both ways* were retired (quests.js `RETIRED` keeps paying their ∎ to saves that finished them; never reuse the ids). A ↔ stamps either one-way version (`make` with `one: "lr"|"rl"`), so once a ↔ is crafted it takes the place, section and name of the one-way machines it covers (`SUPERSEDES`; page `drawFloor` `place`: the ↔ sits where the first old one sat, an axiom's place first, so Double negation stays an axiom; an old machine the hint points at stays visible). The ↔ quests therefore carry the plain names (Double negation, And commutes, Symmetry…), no "both ways". The floor has a search box (`applyFind`, filters in place). A proved implication A → (B → C) becomes the rule "A, B gives C" (`questMachine`), so theorems never need routing through modus ponens; a quest's `takes` caps how many arrows are hypotheses (Swapping takes 1, else it would be a disguised double modus ponens), and keeps `stmt` so the implication can still be stamped whole (needed to feed Or: by cases); `induct` splits a goal into base and step workshops and `assume` opens a workshop for A → B that holds A (and puts A on its bench, free). New workshops start with a copy of the bench they split from (v := 0 in a base case). Nothing finishes by itself (airetho): a workshop is done only after a free `qed` step on a block that is its goal ("✓ use it" on the block, or drag it onto the goal); `withQed` inserts them into reference proofs (at load in quests.js) and into pre-qed saves (page `migrate`, flag `save.qed`); tests use `closeAll`. A → ⊥ is displayed as ¬A everywhere (notation only, no node). A machine that wants ¬X and is fed the X right under a ¬ runs on the ¬X (page `underNeg`). The goal line is tappable like a block: Translator (`unfoldg`), Scanner (`options(..., "g", path)`, rewrites listed only with the Goal lever) and the lever (`rwg`). Tactics (`Q.TACTICS`, their own floor section): induct, assume, `byc` (Contradiction: holds ¬goal, goal ⊥; on sale after And: right and bought for Or: by cases; one step, like every tactic, so that the natural proof is also a short one), `apply` (work backwards: a block P → goal, used up, or a rule whose conclusion fits the goal, one child workshop per premise "1", "2"…; also by dragging a block onto the goal line, while dragging a block onto another tries modus ponens), `have` (Lemma: child "l" proves a typed statement, "c" continues holding it). `rwg` rewrites the goal (Goal lever upgrade, on sale after Associativity of +). Bounties may set `worlds` to limit their machines (Triple negation is implication-only); world-less floors hide other worlds' machines behind a toggle.
